# Spielstand: vollständiges Zustands-Inventar, eigenes Binärformat, keine Migration

Ein Spielstand (Issue #8) schreibt den vollständigen Sim-Zustand plus Seed und Config in eine versionierte Datei und muss bit-identisch weiterlaufen: ein verlorenes ULP divergiert über das chaotische System messbar. `TerrainState` ist die eine Stelle, an der steht, was eine Welt ist; die Kodierung macht `WorldSnapshot`.

Inventar: jedes Feld, das ein `step()` liest, bevor es es schreibt, plus alles, was Rendering und Diagnose sofort nach dem Laden brauchen (kein Einschwingen des Seespiegels). Bewusst großzügig: auch Felder, die `computeFlow` im nächsten Schritt neu ableitet, reisen mit; dann ist „geladen == gespeichert" feldweise prüfbar und der erste Frame ohne erzwungenen Sim-Schritt korrekt. `upliftBase`, `lithBed` und `lithProvince` sind fix je Seed, reisen aber mit: `sculpt` koppelt in die Tektonik, und ein Nachbau per Noise-Code wäre eine zweite Wahrheit. `dropsEmitted` und `dropCarry` gehören zum Determinismus, sonst liefe eine geladene Welt mit anderen Tropfen weiter. Nicht aufgenommen sind Arbeitspuffer und reine Ableitungen wie `underIce`.

Format: roher Block-Transfer der Zahlenfelder als IEEE-754-Bitmuster, Little-Endian, in einem selbstbeschreibenden Container. Eine Welt sind ~30 Felder à n² `Double`, bei n = 832 ≈ 120 MB. Felder mit lauter gleichen Elementen (abgeschaltete oder ruhende Physik) werden als eine Konstante geschrieben; Gleichheit über das Bitmuster, weil ein `Double`-Vergleich −0,0 und 0,0 verschmelzen und NaN nie gleich finden würde. Feldnamen reisen mit, Umbenennen oder Umsortieren ist ein erkennbarer Fehler statt eines stillen Feldversatzes. Länge und FNV-1a-64-Prüfsumme (Integrität, keine Krypto) im Kopf machen eine abgebrochene Speicherung beim Laden sichtbar; die Version wird vor der Prüfsumme geprüft, damit eine Datei aus einer anderen Version „falsche Version" heißt, nicht „defekt". Längen aus der Datei gehen nie ungeprüft in `reserveCapacity`. Geschrieben wird atomar (temporäre Datei plus `rename`).

Die Config liegt als binäres Plist im Container; `SimConfig`, `HydraulicParams` und `HeightBands` sind Codable-synthetisiert, damit jede neue Stellschraube automatisch mitreist (eine vergessene wäre ein stiller Determinismus-Bruch). Eine fehlende Stellschraube in einer alten Datei ist ein harter Dekodier-Fehler statt eines stillen Defaults. Einzige Ausnahme ist `ErosionFilter.Params` (Tupel, handgeschrieben).

Die Datei-Config ist autoritativ: eine geladene Welt läuft mit exakt der Config, mit der sie gespeichert wurde. Ein Mischen aus Datei- und Programm-Config wäre eine dritte, nirgends getestete Konfiguration. Folge: Änderungen an `SimConfig()`-Defaults wirken nur auf neue Welten. Jede Änderung an Inventar, Reihenfolge oder Kodierung erhöht die Version um 1, alte Dateien werden abgelehnt, es gibt bewusst keine Aufwärts-Migration; erhöht wird auch, wenn neue Config-Schlüssel eine alte Datei ohnehin undekodierbar machen, damit der Nutzer die klare Versions-Meldung sieht. Weil jeder Sprung alle Spielstände ungültig macht, kam das Inventar der Klima-Vertikalen (`temperature`, `snow`, `ice`) in einem Sprung (Version 3, #33).

Verworfen:
- JSON und Plist-XML: ~3× so viele Bytes (120 MB → ~380 MB Text) und ein Parser je Zahl. Binäres Plist für die Felder: bit-genau, verpackt aber jedes Element als eigenes Objekt, für 17 Mio. Zahlen unbrauchbar.
- Byte-Swapping je Element: bei 17 Mio. Werten die Laufzeit. Alle Zielplattformen (x86_64, arm64) sind Little-Endian; auf Big-Endian bricht der Zugriff kontrolliert ab.

Betrifft: `TerrainState`, `Terrain.state`, `Terrain.restore`, `WorldSnapshot`, `WorldSnapshot.version`, `WorldSnapshot.encode`, `WorldSnapshot.decode`, `WorldSnapshot.write`, `ErosionFilter.Params` (Codable-Extension), `SimCoreTests/StateInventoryTests.swift`
